# ROM addresses Mac OS 8.1 depends on

Mac OS 8.1 patches this ROM by address: it jumps into the middle of ROM routines and recognises callers by their return addresses. The 954 addresses below were collected from a boot to the Finder on a Mac OS 8.1 disk.

Any of these addresses that moves breaks the corresponding patch. To keep running Mac OS, code up to the last address in this list must keep its exact layout: change code in place with the same size, or branch out to free space after it.

## Columns

**Use**

| Value | Meaning |
|---|---|
| `come-from` | compared with a return address (the patch recognises its caller) |
| `jump-in` | jumped or called to directly |
| `pushed` | pushed as a return address |
| `address` | loaded into a register |
| `held` | held by the System as a fixed value (data, or an operand form the scan does not decode): it did not follow when the ROM was shifted |

**Sources**

| Value | Meaning |
|---|---|
| `boot` | an instruction executed during the boot names the address |
| `ram` | an instruction in RAM after the boot names it (68k opcodes with an absolute or immediate 32-bit operand: `jmp`, `jsr`, `lea`, `pea`, `movea`, `move.l`, `cmpi.l`, `cmpa.l`) |
| `ramdiff` | in RAM, after booting this ROM and a copy with everything from `0x40802BD0` moved by `0x40`, the value stayed where the ROM-made ones moved |
